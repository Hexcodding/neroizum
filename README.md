# НЕЙРОИЗЮМ v2

AI-генератор контент-планов для российских соцсетей: Telegram, VK, MAX, TikTok, Одноклассники. Пользователь рассказывает о своём бизнесе своими словами и получает план на месяц вперёд с готовыми текстами постов, а не с темами и набросками.

Это четвёртое поколение продукта и первое, написанное с нуля осознанно. Предыдущие три (`jj`, `New chance`, `New chance2` в соседних папках) остаются только как справочник наработок — они не подключены к этому проекту и не изменяются.

## Запуск на чистой машине

Нужен Node.js версии 20.11 или новее и git.

```bash
git clone <адрес репозитория>
cd neuroizium-v2
npm install
cp .env.example .env    # в PowerShell: Copy-Item .env.example .env
npm run dev
```

Приложение откроется на `http://127.0.0.1:8080`. Именно по адресу, а не по имени `localhost`: сервер слушает IPv4, а `localhost` на Windows нередко разрешается в IPv6-адрес, и страница не открывается. Без заполненного `.env` интерфейс запустится, но обращения к серверу работать не будут — что вписать, объяснено в `.env.example` и в `docs/supabase-setup.md`.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Разработка с горячей перезагрузкой |
| `npm run verify` | Все проверки подряд: типы, линтер, тесты, сборка, защита промпта |
| `npm run typecheck` | Типы отдельно (клиент, сервер, конфигурация) |
| `npm run lint` | Линтер: границы слоёв, запрет `any`, запрет хардкода цвета |
| `npm run test` | Тесты |
| `npm run build` | Сборка в `dist/` — для клиентов, без панели управления |
| `npm run build:admin` | Сборка панели управления в `dist-admin/`, выкладывается по своему адресу |
| `npm run check:bundle` | Ищет в готовом бандле промпт и панель управления. Требует выполненной сборки |
| `npm run admin-hash` | Считает хеш пароля админки на вашей машине, сам пароль никуда не уходит |
| `./scripts/backup-db.ps1` | Выгрузка базы данных в `backups/` |

**Перед каждым коммитом в стабильную ветку — `npm run verify`.** То же самое выполняется автоматически на стороне GitHub.

## Устройство проекта

```
src/       интерфейс — подробности в src/README.md
supabase/  точки входа для Edge Functions: тонкие обёртки над server/http/
server/    всё, что не должно попасть в браузер — подробности в server/README.md
contracts/ общий словарь клиента и сервера — подробности в contracts/README.md
eslint/    правила границ между слоями
scripts/   служебные скрипты: защита промпта, бэкап базы
docs/      решения и инструкции
```

Зависимости идут только вниз: `app → pages → widgets → features → entities → shared`. Слои `server/` и `entities/` не знают про React. Это не соглашение на словах — попытка нарушить останавливается линтером.

## Что здесь защищено механически

Всё перечисленное — не соглашение на словах, а проверка, которая останавливает сборку.

**Промпт не может попасть в браузер.** Клиентский код не имеет права импортировать из `server/prompt/`, а после каждой сборки `npm run check:bundle` ищет в готовых файлах характерные фразы промпта. В предыдущей версии актив утёк именно через случайный импорт, и никто не заметил, потому что приложение работало нормально.

**Панели управления нет в сборке для клиентов.** Не «спрятана за адресом» — её кода в файлах нет, и это проверяется той же проверкой бандла. Панель собирается отдельной командой.

**Цвет только из токенов темы.** Хардкод вида `bg-blue-500` или `#7c3aed` — ошибка линтера. Иначе светлая тема ломается незаметно: на тёмной всё выглядит правильно.

**Контраст текста считается арифметикой.** Тест берёт токены обеих тем и проверяет отношение яркостей по формулам WCAG. Повод конкретный: `text-muted` какое-то время указывал на цвет подложки, и подписи в тёмной теме отличались от фона на процент.

**Нажимаемые элементы не меньше 44 пикселей**, а поля ввода создаются только в дизайн-системе. Оба правила проверяются по исходному коду целиком, поэтому действуют и на то, что ещё не написано.

**Секреты не попадают в репозиторий.** `.env` в `.gitignore`, а всё, что начинается с `VITE_`, считается публичным по определению — приставка означает, что значение уедет в браузер.

## Ветки

- `main` — стабильная. Сюда попадает только код, прошедший `npm run verify`
- `develop` — рабочая. Здесь ведётся разработка этапа

Перед рискованным изменением ставится метка версии, после каждого завершённого этапа — коммит с описанием на русском.

## Готово и что дальше

Собрано: общий словарь и расписание, ядро генерации с потоком событий, доступ по ключам с лимитами и квотами, база с миграциями, интерфейс — вход, вступление при первом запуске, заявка в четыре шага, экран генерации, план со списком, календарём, правкой и выгрузкой, видимый остаток генераций, панель управления доступами отдельной сборкой.

Развёрнуто и проверено на живой базе: функции выложены в Supabase, доступ по ключу выдаётся, планы генерируются.

Осталось до первых денег: проверка на живых людях и страница оплаты с продлением — вебхук для неё готов, доступы пока выдаются вручную из панели.

Из желательного объёма MVP не сделано ничего: продолжение плана следующим периодом, студия поста со счётчиком под площадку и превью, генерация картинок, публикация в Telegram, улучшение отдельной карточки через AI. Первый пункт самый близкий: сервер уже принимает предысторию и запрещает повторы, не хватает кнопки в интерфейсе.

Порядок работ и объём MVP описаны в `NEUROIZIUM-V2-PROMPT.md` в родительской папке. Принятые технические решения и причины — в `docs/decisions.md`.
