# НЕЙРОИЗЮМ v2

AI-генератор контент-планов для российских соцсетей: Telegram, VK, MAX, TikTok, Одноклассники. Пользователь рассказывает о своём бизнесе своими словами и получает план на месяц вперёд с готовыми текстами постов, а не с темами и набросками.

Это четвёртое поколение продукта и первое, написанное с нуля осознанно. Предыдущие три (`jj`, `New chance`, `New chance2` в соседних папках) остаются только как справочник наработок — они не подключены к этому проекту и не изменяются.

## Запуск на чистой машине

Нужен Node.js версии 20.11 или новее и git.

```bash
git clone <адрес репозитория>
cd neuroizium-v2
npm install
cp .env.example .env    # в PowerShell: Copy-Item .env.example .env
npm run dev
```

Приложение откроется на `http://localhost:8080`. Без заполненного `.env` интерфейс запустится, но обращения к серверу работать не будут — что вписать, объяснено в `.env.example` и в `docs/supabase-setup.md`.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Разработка с горячей перезагрузкой |
| `npm run verify` | Все проверки подряд: типы, линтер, тесты, сборка, защита промпта |
| `npm run typecheck` | Типы отдельно (клиент, сервер, конфигурация) |
| `npm run lint` | Линтер: границы слоёв, запрет `any`, запрет хардкода цвета |
| `npm run test` | Тесты |
| `npm run build` | Сборка в `dist/` |
| `npm run check:bundle` | Ищет промпт в готовом бандле. Требует выполненной сборки |
| `./scripts/backup-db.ps1` | Выгрузка базы данных в `backups/` |

**Перед каждым коммитом в стабильную ветку — `npm run verify`.** То же самое выполняется автоматически на стороне GitHub.

## Устройство проекта

```
src/       интерфейс — подробности в src/README.md
server/    всё, что не должно попасть в браузер — подробности в server/README.md
contracts/ общий словарь клиента и сервера — подробности в contracts/README.md
eslint/    правила границ между слоями
scripts/   служебные скрипты: защита промпта, бэкап базы
docs/      решения и инструкции
```

Зависимости идут только вниз: `app → pages → widgets → features → entities → shared`. Слои `server/` и `entities/` не знают про React. Это не соглашение на словах — попытка нарушить останавливается линтером.

## Три вещи, которые здесь защищены механически

**Промпт не может попасть в браузер.** Клиентский код не имеет права импортировать из `server/prompt/`, а после каждой сборки `npm run check:bundle` ищет в готовых файлах характерные фразы промпта. В предыдущей версии актив утёк именно через случайный импорт, и никто не заметил, потому что приложение работало нормально.

**Цвет только из токенов темы.** Хардкод вида `bg-blue-500` или `#7c3aed` — ошибка линтера. Иначе светлая тема ломается незаметно: на тёмной всё выглядит правильно.

**Секреты не попадают в репозиторий.** `.env` в `.gitignore`, а всё, что начинается с `VITE_`, считается публичным по определению — приставка означает, что значение уедет в браузер.

## Ветки

- `main` — стабильная. Сюда попадает только код, прошедший `npm run verify`
- `develop` — рабочая. Здесь ведётся разработка этапа

Перед рискованным изменением ставится метка версии, после каждого завершённого этапа — коммит с описанием на русском.
