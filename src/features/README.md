# features/ — сценарии

Один сценарий — одна папка.

| Папка | Сценарий | Что внутри без React |
|---|---|---|
| `access/` | Вход по ключу, хранение сессии, остаток генераций, выход | `key-input.ts` — приведение ключа к каноническому виду |
| `plan-form/` | Заявка на план: четыре шага, черновик, проверка полей | `draft.ts` — черновик и перевод его в запрос к серверу |
| `generate-plan/` | Работа генерации: чтение потока, прогресс, остановка | — |
| `edit-post/` | Показ и правка одного поста | — |
| `onboarding/` | Вступление при первом запуске | `intro-state.ts` — признак «уже показывали» |
| `admin/` | Панель управления: вход, выдача ключа, продление, отключение | — |

Папка `admin/` не попадает в сборку для клиентов: она подключается только из `pages/AdminPage.tsx`, а тот — только при включённом признаке админской сборки. Подробности — решение 34 в `docs/decisions.md`.

Вложенных папок `model/`, `service/`, `ui/` здесь нет: сценарии небольшие, и три папки на два файла только удлиняют путь. Правило, ради которого их обычно вводят, соблюдается иначе — **логика без React лежит в отдельном файле рядом**: `draft.ts`, `key-input.ts`. Такой файл вызывается из теста без поднятия интерфейса, и именно поэтому правила не живут внутри компонентов.

Проверка полей берётся из `@contracts` — той же функцией, которой проверяет сервер. Второго набора правил быть не должно: разъехавшись, они дают худший из возможных вариантов — форма разрешает, а сервер отказывает.
