# server/prompt/ — главный актив продукта

Промпт здесь не строка в коде, а версионируемый модуль: блоки лежат отдельными файлами, собираются в `index.ts`, и каждая правка формулировки видна в диффе одного блока.

## Порядок блоков и зачем он такой

| Файл | Что делает |
|---|---|
| `core/role.ts` | Кто модель, для кого работает, приоритет инструкций над текстом пользователя |
| `blocks/business.ts` | Ниша и аудитория — в тегах, как данные |
| `blocks/brand.ts` | Голос, продукты, доказательства, стоп-слова, образцы стиля |
| `blocks/funnel.ts` | Стратегия под цель: пропорции типов и логика по неделям |
| `blocks/rubrics.ts` | Каталог именованных рубрик |
| `blocks/platforms.ts` | Чем посты для разных площадок обязаны отличаться |
| `blocks/anti-teaser.ts` | Zero Click Value — сердце качества |
| `blocks/visual.ts` | Матрица из десяти визуальных стилей |
| `blocks/compliance.ts` | Инфо-план по требованиям ФЗ, только по флагу |
| `blocks/schedule.ts` | Готовая таблица дат и площадок |
| `blocks/continuation.ts` | Что уже создано и что запрещено повторять |
| `core/output-contract.ts` | Формат ответа словами и схемой |

Формат ответа стоит последним осознанно: требования к формату лучше соблюдаются, когда находятся в конце.

## Правила изменения

**Любая правка смысла — с повышением версии в `version.ts`.** Версия сохраняется вместе с планом, иначе через месяц невозможно понять, каким промптом сделан результат и стало ли лучше после правки.

**Блок `anti-teaser.ts` не трогать без необходимости.** Он один отделяет продукт от генератора воды: без него модель охотно пишет «разберём 5 ошибок» и не перечисляет ни одной.

**Данные, а не текст.** Пропорции типов, рубрики и визуальные стили заданы структурами, а не абзацами внутри промпта. Так одну и ту же цифру используют и промпт, и проверка качества результата, и они не могут разойтись.

**Ничего из этой папки не импортируется в браузер.** Проверяется линтером и проверкой собранного бандла; список фраз для поиска утечки — в `scripts/prompt-leak-markers.json`, его актуальность держит тест `leak-markers.test.ts`.

## Откуда взялись пропорции и рубрики

Пропорции типов контента в `blocks/funnel.ts` и список рубрик в `blocks/rubrics.ts` предложены разработчиком и подтверждены заказчиком на этапе 1. В прошлых версиях продукта такой логики не существовало, восстанавливать было нечего.

Это по-прежнему гипотеза, а не проверенная истина: подтверждать её нужно на живых генерациях. Если после запуска окажется, что при цели «продажи» продающих постов много, правка вносится одной строкой в `CONTENT_MIX_BY_GOAL` и автоматически расходится и в промпт, и в проверку качества.
