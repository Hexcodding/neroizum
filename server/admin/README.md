# server/admin/ — админские операции

Выдача и продление доступов, отключение ключей, месячные лимиты, журнал действий администратора: кто, когда и какой доступ создал или продлил.

## Два правила важнее остальных

**Ключ в открытом виде существует один раз** — в ответе на выпуск. Дальше в базе только хеш, и «посмотреть ключ клиента» невозможно даже администратору. Это цена за то, что украденная база не даёт доступов. Тесты проверяют, что ключ не попадает ни в строку базы, ни в журнал.

**Каждое действие пишется в журнал.** Без него нельзя ответить на вопрос «кто и когда отключил клиента», а он возникает всегда. Блокировка и сброс сессии — разные записи: это разные события, хотя обе удаляют сессию.

## Вход

Пароль в базе не лежит: сервер знает только его хеш из секретов проекта. Сессия администратора не хранится, а подписана секретом — срок жизни зашит в токен и подписан вместе с ним, поэтому продлить его снаружи нельзя.

Ограничение попыток входа считается по адресу, определённому сервером, а не по заголовку, который клиент подставляет сам. Счётчик хранится в базе: память отдельного процесса обнуляется при перезапуске, и лимит перестаёт работать.

## Мелочи, которые легко потерять при правке

Блокировка ключа сразу обрывает активную сессию. Иначе отключённый клиент продолжает работать до истечения токена, а администратор считает, что доступ закрыт.

Лимит генераций и дата подписки проверяются на нелепые значения (`1…500`, дата в виде `ГГГГ-ММ-ДД`) с человеческим объяснением ошибки. Ноль в лимите — почти наверняка опечатка, а не намерение.
